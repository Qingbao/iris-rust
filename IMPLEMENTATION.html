Pipeline

Same algorithmic stages as the original Masek / Daugman pipeline. Each stage is one module in src/.

1. Load casia.rs — Walk {subject:03}/{session}/{subject:03}_{session}_{k}.bmp; decode BMP → row-major Array2<f64> grayscale.
2. Segment iris & pupil daugman.rs + segment.rs — Coarse 3-D Hough space search over the integro-differential operator ∂/∂r ∮ I(x,y)/2πr, then a 16-pixel fine search around the coarse peak. Outer (limbus) search restricted to side-arcs to skip eyelids.
3. Find eyelids eyelid.rs — imageproc::edges::canny on strips above & below the pupil, then a hand-rolled Radon transform (180 θ-bins × ⌈√(h²+w²)⌉ ρ-bins) for the dominant line.
4. Mask noise segment.rs — Above-top-eyelid + below-bottom-eyelid + pixels < 80 (CASIA eyelash threshold) are marked None.
5. Polar unwrap normalize.rs — Daugman rubber-sheet with pupil↔iris offset correction; bilinear sample to a 22-row polar array, trim the outer 2 rings → final shape (20, 240). None propagates through interpolation.
6. Feature encode encode.rs — Per polar row: forward FFT (rustfft) × 1-D log-Gabor frequency response × inverse FFT. Phase quantize each complex sample into 2 bits: bit₀ = Re>0, bit₁ = Im>0. Result is a 20×480 = 9600-bit template plus a 9600-bit noise mask (NaN-region ∨ |E|<10⁻⁴).
7. Match matching.rs — For each of 17 circular column shifts s ∈ −8..=8: (t₁≪s ⊕ t₂) ∧ ¬(m₁≪s ∨ m₂), divide popcount by valid-bit count, keep the minimum. Operates on packed BitVec<u64>.
8. EER bin/iris.rs — Sweep threshold 0..1 in 0.01 steps, compute FMR & FNMR, return the crossover.

Implementation notes worth re-reading

Bit-layout invariants

Three shapes are load-bearing across modules; change any one and the matching code's bit arithmetic falls apart:

  • Polar unwrap: Array2<Option<f64>> of shape (20, 240).
  • Template & mask: BitVec<u64, Lsb0> of 9600 bits, conceptually (20 rows, 480 cols) row-major. Column c = 2 × angular_idx + {0:Re, 1:Im}.
  • Shift sweep: each unit of shift moves two bit columns (one real + one imaginary), so shift_columns(±1) rotates by 2 of the 480 columns.

NaN vs Option<f64>

MATLAB's pipeline marks noise pixels with literal NaN values; the Rust port replaces this with Option<f64>. Bilinear interpolation propagates None: if any of the four corner samples is None, the output is None. The encoder fills None cells with the row-mean before FFT (mirroring the MATLAB averaging step), but keeps the original noise mask intact for the matching stage.

FFT normalization

MATLAB's ifft divides by N; rustfft does not. The encoder rescales the inverse FFT output by 1/N so the |E| < 10⁻⁴ amplitude threshold for the noise mask matches MATLAB's behaviour. Sign-based phase quantization is unaffected.

Diagnostic JPGs

With --diagnostics <DIR>, each enrolled image writes three files mirroring the MATLAB diagnostics/ convention from createiristemplate.m:

  • <stem>-segmented.jpg — original eye with iris & pupil circles drawn in white.
  • <stem>-polar.jpg — the 20×240 polar unwrap (vertical = radial, horizontal = angle).
  • <stem>-noise.jpg — binary noise mask (white = excluded).

Out of scope

  • Hough algorithm — only the better-performing Daugman branch was ported. Adding Hough later means swapping daugman.rs for a hough.rs behind a trait.
  • MATLAB .mat interop — templates persist as a single bincode file, not a .mat file.
  • Bit-exact match against MATLAB — Canny / FFT ordering differences are tolerated since the EER target is "same ballpark."
